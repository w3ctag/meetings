### Private Browsing

Heather: Definition of private browsing (https://www.w3.org/2001/tag/doc/private-browsing-modes/) came up as a part of the Digital Credentials discussions. The Wallet cannot know if the user is in private mode or not.

Marcos: I think the conclusion was to NOT differ for Digital Credentials depending on private browsing.

Brian: Doesn’t that finding suggest that creators of new features should consider if private browsing should change the behavior?

Jeffrey: At the time that this was written, the argument was private browsing mode was only saying to the browser "don't save my stuff." Court ruling that if a feature i called "icognito," users expect that they are stealth. I think we should consider what more Private Browsing should do. For example, for Digital Credentials, if wallets had a private mode, browsers could forward that bit.

Marcos: I don’t disagree with the idea. We previously discussed general-purpose API vs use case specific API, e.g. could mandate use of zero-knowledge proof when in private mode.

Jeffrey: Wallet app could remember your use of information, and if you’re in private mode, you could ask the wallet to not remember the information.

Marcos: Think that is the tangent in the working group. The browser mediates, but there is the huge number of wallets. Putting conformance requirements on them is hard. There’s nothing normative.

Jeffrey: It might be helpful to keep a list of things that differ. But that can only be non-normative, as private browsing currently is non-normative. There can be options in the spec. We could consider keeping that in the spec so the browser can turn it on.

Heather: So, is there work here for the TAG?

Jeffrey: It could be worth updating the document. I volunteer to review, not write. Does anyone volunteer to write?

Christian: How common is this? Just Digital Credentials?

Heather: It came up in DC, but wanted to ask the broader question.

Lola: It doesn't come up very often, but it's not the first time. Over last 2 years, we've had very similar discussions. 1) Not necessarily urgent, but might be worth having something.

Marcos: There is the more drastic mode, called lockdown mode. Not sure if that’s discussed in the document.

Jeffrey: I’m not sure this is specified anywhere. Does Safari change its behavior?

Marcos: It does; it turns IndexedDB and a whole lot of other APIs off.

Christian: What would you want to update in the document? I could imagine doing that, lockdown mode is an interesting addition, but what else?

Jeffrey: I think section 3 doesn’t say the kinds of variations that we would expect to see in how a specification should describe those variations. I think the answer is, when there’s a difference in private browsing mode. The spec should state both options, and declare both of them conforming. Lockdown mode may be an additional vector.

Brian: But how does this affect IDB?

Jeffrey: We should specify which of those things happen. If an API disappears during lock down mode, this is different from throwing an error.
