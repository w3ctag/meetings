#### Discussion on Appropriate use of Service Worker

Xiaocheng: Question about what service workers are supposed to do. My understanding is they're for things like fetch handling, notification pushing, etc. That they should not perform business logic of the app. But some people say they should be doing that. What's the opinion here?

Martin: I share your view - a service worker allows a site to be activated according to a specific need when there is no window/tab to take that request. E.g. decide whether or not to show a window as a result of some notification; or handle a fetch. We discussed Background Sync but were not able to determine whether it was a suitable use case, because it wasn't clear if it fit the model. For background work, we have shared workers that can do async procesing.

Xiaocheng: I read the spec but didn't find anything directly discouraging business logic - other than that the lifetime of the service worker is not guaranteed, which makes it unsuitable for business logic.

DanA: Who is discussing the use of service workers for business logic? Are they discussing making them more friendly to background logic?

Xiaocheng: Mini-app architects.

DanA: Might be useful to make a TAG statement (finding) on this, to discourage misuse. As we have with fingerprinting etc.

Xiaocheng: Does that mean we need to investigate how much service worker has been misused?
Example of misuse/creative use: use SW to implement synchronous communication between a dedicated worker and the main thread. It takes an async call into a synchronous XMLHttpRequest.

Martin: That's bad. Another use I've seen is polyfill for the filesystem API - streaming content to a local file. With SW you can stream to it and force a download.

I don't know that it is, but we have done similar in the past - e.g. reserach towards the evergreen web finding (fixed/non-updating UAs being an antipattern). Ask for volunteers in the TAG Slack? It's within our remit - especially if there's standardization work that's going in the wrong direction, or there is misuse of specs. We could push it back to the SW people, that it should be less easy to do these abuse cases/antipatterns.

Christian: Web Almanac - if we wanted to get some data, this may be a good chance, as they are about to start their next crawl.

DanA: What's the user need in this case? I select some text and want AI to comment on it?

DanA: But the browser, rather than the site, will be choosing the LLM.

Martin: Ostensibly they are meant to provdie the same features - but the user experience will vary a lot. They may also use different models depending on device (mobile vs desktop) within a browser.

Christian: I think it's good and needed - sentiment analysis; data categorization; extracting info from email; multimodal pasting capabilities. I understand the concern that it binds the browser to a model - my understanding is that is not inherent in the API. Could use the model that's already on the device. This may be the current implementation but it's not necessarily the case.

Martin: I understand that in the Chrome case they are not going to use the underlying platform model.

Xiaocheng: Thinking about user need: the prompt API may be general enough to drive other lower-level APIs and build a full AI app. The potential is huge here. I am still wondering about the question I raised before which is 'what does interoperability' mean here? Martin: The question is 'how would you write a test case?'

Xiaocheng: You could use another model to test it.

Martin: reward hacking

That experience already exists on many sites.  I can choose models on some sites.  Lots of capabilities, all running on servers.  How do we make sure that information doesn't leak between origins?

Martin: this is part of why the Chrome team doesn't want to use the platform level API - to avoid such leakage.  The platform API might take inputs into a common context that is not origin-aware.

DanA: Depends on the threat model. We need to find out how to respond appropriately to this.

Matthew: how much can this reasonably do that's use ful for the user?
